Developers

Give your agent a tab.

Two key files, one signed limit, and a fetch that knows how to pay. Works from the command line, from your own code, or inside Claude Code.

Five minutes, sandbox money.

tab needs Node 22.13 or newer and nothing else. The sandbox ledger settles instantly and costs nothing, so the whole loop runs on one machine.

The demo script does all of this for you, including a priced demo API and a catalog, if you would rather watch first.

$ git clone <the tab repo> && cd tab && npm install
$ npm run demo   # keys, sandbox money, demo API :4101, gateway :1402, catalog :1403
# 1. a key for the owner of the money, and one for the agent
$ tab key new --out keys/owner.json
$ tab key new --out keys/agent.json

# 2. the owner signs a limit for that agent, once
$ tab mandate issue --owner keys/owner.json --agent keys/agent.json \
    --budget 25 --window day --max-per-call 0.05 --days 30 \
    --out keys/mandate.json

# 3. sandbox money on a gateway's ledger (development only)
$ tab mint --wallet keys/owner.json --amount 25 --db tab.db

# 4. pay for a request
$ tab fetch --agent keys/agent.json --mandate keys/mandate.json \
    http://127.0.0.1:1402/quote
✓ paid $0.01 · 200 OK

From your own code.

The client wraps fetch. On a 402 it reads the price, checks it against your own per-call ceiling, signs a payment, and retries exactly once.

If the price is over your ceiling, or your veto says no, it throws before anything is sent. The gateway never sees a credential you did not agree to.

  • TabClient keeps the agent key and mandate and exposes fetch.
  • tabFetch(url, init, options) is the one-shot form.
  • receiptOf(response) returns the receipt, or null when the route was free or the call was voided.
  • PaymentRefused is thrown when the client itself declined to pay.
import { TabClient, receiptOf, PaymentRefused } from 'tab/client';

const client = new TabClient({
  agent, mandate,
  maxPerCallUsd: '0.05',                       // your own ceiling, on top of the limit
  onChallenge: (challenge, req) => req.amountUsd !== '0.05', // optional veto
});

try {
  const res = await client.fetch('https://api.lingua.example/v1/translate', {
    method: 'POST', body: JSON.stringify({ text: 'Hello, world', to: 'ja' }),
  });
  const receipt = receiptOf(res);            // { amount, resource, rail, ref, … } or null
} catch (e) {
  if (e instanceof PaymentRefused) console.log('declined:', e.reason);
}

Inside Claude Code.

tab mcp is a Model Context Protocol server that runs where Claude Code runs. It needs the agent key, the mandate, and network access to the gateway and catalog. Claude never sees the owner key.

It exposes five tools:

tab_limits
What this agent may spend, and what is left.
tab_search
Search the catalog by keywords and an optional price ceiling.
tab_discover
Read a gateway's own service list.
tab_fetch
Make a paid request.
tab_balance
Available balance on a gateway.
// .mcp.json next to your project
{ "mcpServers": { "tab": {
  "command": "node",
  "args": ["/opt/tab/dist/src/cli.js", "mcp"],
  "env": {
    "TAB_AGENT":        "/opt/tab/keys/agent.json",
    "TAB_MANDATE":      "/opt/tab/keys/mandate.json",
    "TAB_MAX_PER_CALL": "0.05",
    "TAB_CATALOG":      "https://catalog.example.com"
  }
} } }

Or for every project: claude mcp add --scope user tab -e TAB_AGENT=… -e TAB_MANDATE=… -- node /opt/tab/dist/src/cli.js mcp

What a limit says.

A mandate is a small signed object. The owner signs it once; the agent carries it with every payment; the gateway enforces it on every request. It is not secret, but it grants spending, so treat it like a key.

A second, client-side ceiling lives with the agent (--max-per-call or maxPerCallUsd) and is checked before any request is signed.

TermFlagMeaning
Budget--budget 25Total the agent may spend in the window, in USD.
Window--window total|dayWhether the budget is for the mandate's lifetime or per UTC day.
Per request--max-per-call 0.05Ceiling on any single request.
Services--allow realmWhich gateways may be paid, by realm name, with globs. Repeatable.
Expiry--days 30When the mandate stops working.

When a payment is refused.

A refused payment is a plain 402 with a problem document that names the reason, and a fresh challenge so a corrected retry can follow. Nothing is charged on a refusal. The client retries once; a second 402 is an answer.

ReasonWhat it means
mandate-exceededThe per-request cap or the window budget would be exceeded.
mandate-deniedThis gateway's realm is not in the mandate's allow list.
mandate-invalidThe mandate is malformed, badly signed, or expired.
insufficient-fundsThe owner's balance or allowance cannot cover the price.
payment-expiredThe challenge was too old. Retry to get a fresh one.
verification-failedThe signature or the signed request does not match what arrived.
upstream-failed502. The service did not answer. Nothing charged.
