Get started
Developers

Your agent can buy things in five minutes.

One command creates a wallet, signs a spending limit and loads a dollar of starter credits. Your agent can then pay for web search, translation, speech to text and more, per request, with a receipt for every call. When you want real money, the same keys work with USDG on Robinhood Chain.

Start here.

tab needs Node 22.13 or newer and nothing else. init writes an owner key, an agent key and a signed limit of $1.00 a day to ~/.tab, then claims $1.00 of starter credits from the public gateway at pay.paidwithtab.com.

The second line is a real paid request. It costs $0.001 of those credits and returns today's exchange rates from the European Central Bank. The third line gives the same wallet to Claude Code.

Starter credits are sandbox money that only pay.paidwithtab.com accepts. Everything else about the call is real: the price, the limit check, the upstream API, the receipt.

$ npx paidwithtab init
owner key   ~/.tab/owner.json (new)
agent key   ~/.tab/agent.json (new)
mandate     ~/.tab/mandate.json: 1.00/day, 0.05 per call, 90 days
credits     1.00 starter credits from pay.paidwithtab.com

$ npx paidwithtab fetch "https://pay.paidwithtab.com/fx/latest?base=USD&symbols=EUR,JPY"
paid 0.001 (ledger:hBdV9yRwXKy_-wJJ)
{"amount":1.0,"base":"USD","date":"2026-10-09","rates":{"EUR":0.89,"JPY":152.3}}

$ claude mcp add --scope user tab -- npx -y paidwithtab mcp

Inside Claude Code.

tab mcp is a Model Context Protocol server that runs where Claude Code runs. After init, one line registers it for every project. Claude gets five tools and can never spend past the limit you signed. It never sees the owner key.

tab_search
Search the catalog by keywords, with an optional price ceiling.
tab_fetch
Make a paid request and get the result plus the receipt.
tab_limits
What this agent may spend, and what is left today.
tab_balance
Available balance on a gateway.
tab_discover
Read a gateway's own service list.

Then ask for something: "search the web for the latest on HTTP 402 through tab", or "look up the weather in Lisbon through tab". Claude finds the route, pays, and shows you the receipt.

# once, for every project, after npx paidwithtab init
$ claude mcp add --scope user tab -- npx -y paidwithtab mcp

# or pin your own keys and catalog in .mcp.json
{ "mcpServers": { "tab": {
  "command": "npx", "args": ["-y", "paidwithtab", "mcp"],
  "env": {
    "TAB_AGENT":        "/path/to/agent.json",
    "TAB_MANDATE":      "/path/to/mandate.json",
    "TAB_MAX_PER_CALL": "0.05",
    "TAB_CATALOG":      "https://paidwithtab.com"
  }
} } }

With no env set, tab mcp uses the agent and mandate from ~/.tab and the public catalog.

From your own code.

The client wraps fetch. On a 402 it reads the price, checks it against your own per-call ceiling, signs a payment, and retries exactly once. If the price is over your ceiling, or your veto says no, it throws before anything is sent.

  • TabClient keeps the agent key and mandate and exposes fetch.
  • receiptOf(response) returns the receipt, or null when the route was free or the call was voided.
  • PaymentRefused is thrown when the client itself declined to pay.
import { TabClient, receiptOf, PaymentRefused } from 'paidwithtab/client';

const client = new TabClient({
  agent, mandate,                               // from ~/.tab, or your own files
  maxPerCallUsd: '0.05',                        // your own ceiling, on top of the limit
});

try {
  const res = await client.fetch('https://pay.paidwithtab.com/search', {
    method: 'POST',
    body: JSON.stringify({ query: 'HTTP 402 payment required', max_results: 3 }),
  });
  const { results } = await res.json();
  const receipt = receiptOf(res);             // { amount: '10000', rail: 'ledger', ref, … }
} catch (e) {
  if (e instanceof PaymentRefused) console.log('declined:', e.reason);
}

Real money, when you want it.

The same two key files work on chain. The owner key derives an Ethereum address; so does the agent key. On Robinhood Chain the owner approves the agent to spend up to a limit, and each paid request is one transfer from the owner's wallet to the seller's, broadcast only after the service answered. The gateway never holds your funds.

Try it free first. testnet.paidwithtab.com serves the same nine routes for test USDC, which is open mint. mainnet.paidwithtab.com takes USDG, the dollar on Robinhood Chain mainnet. The first mainnet payment through tab settled on October 11, 2026: see the transfer.

Testnet
Chain id 46630. The owner address needs test ETH from a faucet; the script mints the test dollars.
Mainnet
Chain id 4663. The owner address needs a little ETH for gas and USDG to spend. Send both from the Robinhood app on the Robinhood Chain network.
# the owner's address, to fund
$ tab evm address ~/.tab/owner.json

# give the agent gas, approve it to spend, sign a limit for the mainnet realm
$ tab evm fund --from ~/.tab/owner.json --to ~/.tab/agent.json --eth 0.0005 \
    --rpc https://rpc.mainnet.chain.robinhood.com
$ tab evm approve --owner ~/.tab/owner.json --agent ~/.tab/agent.json --amount 5.00 \
    --token 0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168 --rpc https://rpc.mainnet.chain.robinhood.com
$ tab mandate issue --owner ~/.tab/owner.json --agent ~/.tab/agent.json \
    --budget 1.00 --window day --max-per-call 0.05 --allow mainnet.paidwithtab.com \
    --days 30 --out ~/.tab/mandate-mainnet.json

# pay in USDG
$ tab fetch --agent ~/.tab/agent.json --mandate ~/.tab/mandate-mainnet.json \
    -X POST -d '{"query":"robinhood chain"}' https://mainnet.paidwithtab.com/search
paid 0.01 (evm:0x…)

# the kill switch
$ tab evm revoke --owner ~/.tab/owner.json --token 0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168 \
    --rpc https://rpc.mainnet.chain.robinhood.com

What a limit says.

A mandate is a small signed object. The owner signs it once; the agent carries it with every payment; the gateway enforces it on every request. It is not secret, but it grants spending, so treat it like a key.

A second, client-side ceiling lives with the agent (--max-per-call or maxPerCallUsd) and is checked before any request is signed. init issues $1.00 a day, $0.05 a call, for 90 days; issue your own with any numbers you like.

TermFlagMeaning
Budget--budget 1.00Total the agent may spend in the window, in USD.
Window--window total|dayWhether the budget is for the mandate's lifetime or per UTC day.
Per request--max-per-call 0.05Ceiling on any single request.
Services--allow realmWhich gateways may be paid, by realm name, with globs. Repeatable.
Expiry--days 30When the mandate stops working.

When a payment is refused.

A refused payment is a plain 402 with a problem document that names the reason, and a fresh challenge so a corrected retry can follow. Nothing is charged on a refusal. The client retries once; a second 402 is an answer.

ReasonWhat it means
mandate-exceededThe per-request cap or the window budget would be exceeded.
mandate-deniedThis gateway's realm is not in the mandate's allow list.
mandate-invalidThe mandate is malformed, badly signed, or expired.
insufficient-fundsThe owner's balance or allowance cannot cover the price, or the agent has no gas.
payment-expiredThe challenge was too old. Retry to get a fresh one.
verification-failedThe signature or the signed request does not match what arrived.
upstream-failed502. The service did not answer. Nothing charged.
