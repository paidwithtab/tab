Providers

Price your API. Get paid per request.

You have an HTTP API. You write one JSON file that says what each route costs, and run one process in front of it. Agents find your routes in the catalog, pay before you answer, and you receive USDG on Robinhood Chain for every successful call. No accounts, no billing code, no invoices.

This is how our own gateways run.

Everything on this page is what we use for pay.paidwithtab.com, testnet.paidwithtab.com and mainnet.paidwithtab.com. Those three gateways serve nine routes over Tavily, DeepL, Deepgram, Jina Reader, Wikipedia, Open-Meteo and the European Central Bank, and they have settled real payments. Their spec is public, and their discovery documents are what agents read.

One file describes your prices.

A spec names your gateway (its realm), says who gets paid, and lists your services. Each service points at your existing upstream and lists priced routes. Prices are USD strings. A price of "0" is forwarded free. Paths may have parameters like /v1/things/:id. Anything not listed is not proxied.

realm
Your gateway's name, usually its hostname. Owners allow-list realms in the limits they sign.
recipient
The wallet that receives payments: your seller key's public id, and on chain its address.
prefix
Mounts a service under a path. Empty for the root.
upstream
Where tab forwards paid requests. May include a path.
upstream_headers
Headers tab injects, such as your real API key. Callers never see them. ${NAME} is read from the environment.
requires
Variables the service cannot run without. If one is unset at start, the service is skipped and logged, not listed broken.
public_receipts
Publish the last 200 receipts for the catalog's live feed.
// spec.json for an API of your own
{
  "realm": "api.yourcompany.com",
  "recipient": "<your seller key's public id>",
  "public_receipts": true,
  "services": [
    {
      "name": "yourapi",
      "prefix": "",
      "upstream": "http://127.0.0.1:8080",
      "upstream_headers": { "X-Internal-Key": "${INTERNAL_KEY}" },
      "description": "What your API does, in one line buyers can search for",
      "routes": [
        { "method": "POST", "path": "/v1/analyze", "price": "0.02",
          "description": "Analyze a document. JSON body {\"url\": \"...\"}" },
        { "method": "GET",  "path": "/v1/status", "price": "0",
          "description": "Free health check" }
      ]
    }
  ]
}

List your API in the catalog today.

Three commands. The gateway is one process in front of your API: it answers unpaid requests with a price, verifies payments, forwards paid requests, and settles only when you answered successfully. Announce it and the catalog reads your gateway's own service list, so the listing stays in sync with your spec.

The catalog accepts any public origin that serves a valid discovery document over HTTPS. Your routes appear at paidwithtab.com/catalog and in agent searches within a minute.

Run it behind nginx, Caddy or a Cloudflare tunnel with TLS, and bind the gateway to loopback so only the proxy reaches it. The deployment guide has a complete setup, including the systemd units we use.

# 1. a seller key: payments go to it
$ npx paidwithtab key new --out keys/seller.json

# 2. put its public id in spec.json as "recipient", then serve
$ INTERNAL_KEY=... npx paidwithtab serve --spec spec.json --port 1402 \
    --origin https://api.yourcompany.com \
    --announce https://paidwithtab.com

# 3. check what agents will see
$ curl https://api.yourcompany.com/.well-known/tab
{ "ver": "tab/0", "realm": "api.yourcompany.com", "rail": "ledger", "services": [ … ] }

What happens to each request.

Your API sees only paid requests, with three extra headers telling you who paid. The buyer's payment header is stripped and your configured upstream headers are injected.

You are paid when you answer with a 2xx. If your API fails or is unreachable, the reservation is released and the caller is not charged. The failure mode is always in the buyer's favor, which is what makes agents willing to pay up front.

  1. Unpaid requestAnswered with 402, the price, and a challenge. Nothing reaches your API.
  2. Paid requestSignature, limit, and funds are verified. The amount is reserved.
  3. Forwarded to youWith Tab-Payer, Tab-Owner and Tab-Hold headers for attribution.
  4. You answer 2xxThe payment settles. The response carries a signed receipt.
  5. You answer anything elsePassed through with Tab-Void. The reservation is released, nothing charged.

How you get paid.

Every gateway settles on one rail. Start on the sandbox ledger while you integrate: balances live in the gateway's own database, and --faucet can hand new buyers starter credits. Then switch the spec to real value.

On Robinhood Chain, each payment is a USDG transfer from the buyer's owner wallet straight to your address, one per request, broadcast only after you answered. The gateway holds no payment key and never custodies funds. Receipts carry the transaction hash, and the catalog links each one to the explorer.

Before real money.

  • Serve behind TLS, and bind the gateway to loopback so only the proxy reaches it.
  • Keep provider keys in an env file the unit reads, never in the spec. Name them in requires.
  • Back up the gateway's database file. It holds ledger balances and the record of every hold and receipt.
  • Turn on public_receipts only if you are happy to expose payer and owner wallet ids.
  • Price above what your upstream charges you. Buyers see the price before they pay; you see nothing until they do.
