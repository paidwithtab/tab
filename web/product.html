A tab for every agent.

tab sits between your agent and the services it uses. You set a limit once. The agent pays per request, and every payment comes back with a receipt.

Three things make a tab.

Nothing else is required. No accounts, no API keys, no invoices at the end of the month.

01

A limit

You sign a spending limit for one agent: how much in total or per day, how much per request, which services, and until when. You sign it once, offline, and keep your keys.

02

Payments

The agent pays as it goes, one request at a time, at the price the service publishes. A service is paid only when it answers successfully. Failed calls cost nothing.

03

Receipts

Every paid response carries a signed receipt: what was bought, for how much, from whom, and where the money moved. Receipts are yours to keep and verify.

How one request works.

The agent never handles money directly and the service never handles identity. tab sits between them and does both.

Everything below happens in the time of a single HTTP request, with one retry.

  1. The agent needs somethingA translation, a search, a document read. It asks like it would ask any API.
  2. tab finds a serviceServices are listed in a catalog with their prices, so the agent can choose before it spends.
  3. The service names its priceThe first request is answered with a price and a challenge instead of the result.
  4. tab checks the limitPer-request cap, remaining budget, allowed services, expiry. If anything fails, nothing is paid.
  5. The agent paysIt retries with a signed payment. The money is reserved, not yet moved.
  6. The service respondsOn success the payment settles and the response carries a receipt. On failure the reservation is released.

Built for three people.

Each one gets a smaller job than they have today.

Whoever owns the budget

Decide once how much an agent may spend and on what. You are never online during a payment, and the agent can never exceed what you signed, whatever it is told.

Whoever builds the agent

Use any HTTP client, the tab command line, or the MCP server inside Claude Code. Paying for a request is one call. Refusals come back as clear reasons.

Whoever runs the service

Price your routes in one JSON file and put tab in front of your API. You get paid per request, before you answer, with no billing system to build.

Real money, or none yet.

Start on the sandbox ledger: free balances the gateway keeps locally, instant, ideal for development and tests.

When it matters, switch a service to USDC on Robinhood Chain. Your funds stay in your own wallet. You allow the agent to move up to the limit, and tab moves only what each request costs, only after the service has answered.

What a tab is not.

Not a subscription

Nothing recurs. An agent that does nothing spends nothing.

Not an account

No sign-up on either side. A key and a signed limit are the whole identity.

Not a wallet the agent controls

The agent can spend within the limit and nothing beyond it. Revoke the allowance and it stops.
